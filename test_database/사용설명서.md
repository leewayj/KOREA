# 테스트 데이터베이스 사용법

`library_test.db`는 최신 KOREA 스키마로 생성한 독립 SQLite 테스트 DB다. 기존 프로젝트의 library.db를 교체하지 않는다.

## 사용자

| 학번 | 이름 | 대학 | 학과 |
|---|---|---|---|
| 2026123456 | 홍길동 | 소프트웨어융합대학 | 컴퓨터학부 |
| 2026987654 | 이하냥 | 소프트웨어융합대학 | 수리데이터사이언스학과 |

학번은 문자열로 저장한다. 사용자 식별 정보는 `users`, 이름·대학·학과는 `user_profiles`에 저장한다. API에서는 각각 `s_id`, `name`, `college`, `department` 필드에 대응한다. 두 학번으로 바로 로그인할 수 있으며 사전 발급 세션은 없다.

## 층·방·좌석

| 층 ID | 층 이름 | 방 ID | 방 이름 | 방 코드 | 표시 좌석 번호 | 좌석 전역 ID |
|---|---|---|---|---|---|---|
| 1 | 2F | 1 | 제1열람실 | R1 | 1~72 | 1~72 |
| 2 | 4F | 2 | 제2열람실 | R2 | 1~72 | 73~144 |
| 2 | 4F | 3 | 집중열람실 | Focus | 1~72 | 145~216 |
| 2 | 4F | 4 | 노상일 | HOLMZ | 1~72 | 217~288 |

층 이름은 `floors.name`에 저장한다. 현재 스키마에서 필요한 층 코드는 각각 `2`, `4`로 설정했다. 층 ID 1은 2F, 층 ID 2는 4F이므로 API의 floor_id에는 1 또는 2를 사용한다.

좌석의 표시 번호는 방마다 1부터 시작한다. 예약 API의 seat_id에는 중복되지 않는 전역 ID를 사용한다. 예를 들어 제2열람실 1번 좌석의 seat_id는 73이다.

예약·이용 좌석 이력·로그인 세션은 비어 있다. 관리자 계정은 아래 테스트 계정 1개를 제공한다. 좌석 착석 상태는 288개 모두 UNKNOWN으로 시작한다. 센서 정보나 예약을 임의로 추가하지 않는다.

## API에서 사용

기존 서버를 종료한 뒤 본인의 프로젝트 루트에서 다음을 실행한다. 테스트 DB 파일의 전체 경로를 입력한다. 설정은 해당 PowerShell 창에만 적용된다.

```powershell
$projectRoot = (Read-Host 'KOREA 프로젝트 루트 경로').Trim().Trim('"')
Set-Location -LiteralPath $projectRoot
$pythonExe = Join-Path $projectRoot '.venv/Scripts/python.exe'
$env:KOREA_DB_PATH = (Read-Host 'library_test.db 전체 경로').Trim().Trim('"')
& $pythonExe -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Python 실행 파일·서버 바인딩 주소·포트는 본인 환경에 맞게 바꾼다. Swagger에서 `/auth/login`에 다음과 같이 학번을 입력한다.

```json
{"s_id": "2026123456"}
```

## 테스트 관리자 로그인

- 관리자 ID: `admin`
- 비밀번호: `admin`

`POST /admin/auth/login`에서 다음 본문으로 로그인한다.

```json
{"username": "admin", "password": "admin"}
```

응답의 `access_token`을 Swagger의 AdminSession에 입력하면 관리자 API를 사용할 수 있다. DB에는 평문 비밀번호 대신 기존 API와 동일한 PBKDF2 해시로 저장한다.

일반 관리자 생성 도구는 비밀번호 8자 이상을 요구한다. 이 계정은 요청한 테스트 DB에만 초기 데이터로 추가하며, 일반 계정 생성 규칙과 API 코드는 바꾸지 않는다. 새 테스트 DB 생성 스크립트도 같은 계정을 추가한다. SQL seed만 실행하면 관리자 계정은 추가하지 않는다.

기본 DB로 복귀하려면 서버를 종료하고 `KOREA_DB_PATH` 환경변수를 제거한 뒤 재시작한다.

## 새 테스트 DB 생성

`create_test_db.py`와 `seed.sql`이 있는 폴더에서 실행한다. 프로젝트 루트와 새 DB 경로를 입력한다.

```powershell
$projectRoot = (Read-Host 'KOREA 프로젝트 루트 경로').Trim().Trim('"')
$pythonExe = Join-Path $projectRoot '.venv/Scripts/python.exe'
$outputPath = Read-Host '새 테스트 DB 전체 경로(기존 파일 사용 불가)'
& $pythonExe ./create_test_db.py --project-root $projectRoot --output $outputPath
```

출력 폴더는 미리 준비한다. 기존 파일을 덮어쓰지 않는다. `seed.sql`은 이 테스트 DB의 초기 데이터 전용이며 기존 프로젝트 DB에 실행하지 않는다. 같은 테스트 DB에서 재실행해도 중복 키 오류가 발생하지 않지만, 이미 존재하는 행의 값을 수정하거나 기존 예약을 초기화하지도 않는다.
